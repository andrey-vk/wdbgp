# Адаптеры фидов

## Формат фидов

Канонический формат пользовательского фида:

```json
{
  "entries": [
    {
      "category": "ai",
      "service": "openai",
      "cidrs": ["104.18.0.0/16", "172.64.0.0/13"]
    }
  ]
}
```

Поддерживаются также один entry-объект и массив entry-объектов. Префиксы
нормализуются и дедуплицируются. Выбор категории автоматически включает новые
сервисы, которые позже появятся в ней.

## Параметризация через поле data

Каждый фид может содержать опциональное поле `data` — JSON-строку для
параметризации адаптера. Это позволяет использовать один адаптер для нескольких
фидов с разными настройками. Например, адаптер SRS можно переиспользовать для
разных geoip-файлов, задав `category` и `service` в данных фида:

```json
{"category": "Russia", "service": "geoip-ru"}
```

Поле `data` доступно внутри адаптера как `feed.data` (строка с JSON —
используйте `JSON.parse()`).

## Встроенные адаптеры

В дистрибутив входят адаптеры для канонического JSON, OpenCCK, IPRanges и
sing-box SRS. Для каждого фида выбирается один адаптер.

- **Canonical JSON** — обрабатывает канонический формат фидов, описанный выше.
- **OpenCCK** — обрабатывает формат фидов OpenCCK с широким покрытием сервисов
  на базе ASN и общей инфраструктуры.
- **IPRanges** — загружает merged IPv4/IPv6-списки из
  [antonme/ipranges](https://github.com/antonme/ipranges) и раскладывает их по
  отдельным сервисам каталога.
- **sing-box SRS** — скачивает бинарные файлы `.srs`, распаковывает (zlib),
  разбирает бинарный формат (версии 1–5) и извлекает `ip_cidr`-записи.
  Используйте `api.srsGet(url)` для прямого доступа в пользовательских
  адаптерах.

## API адаптеров

Адаптеры фидов являются JavaScript-программами, хранятся в базе данных и
редактируются из админки. Адаптер должен определять функцию:

```javascript
function sync(feed, api) {
    const data = JSON.parse(api.httpGet(feed.url));
    return data.entries;
}
```

### sync(feed, api)

Функция возвращает объекты с полями `category`, `service` и `cidrs`.

### api.httpGet(url)

Выполняет HTTP GET запрос и возвращает тело ответа как строку.

### api.srsGet(url, cfg)

Скачивает и разбирает бинарные файлы sing-box SRS. `cfg` — опциональная
JSON-строка (например, `{"cidrs":true}`), управляющая извлекаемыми данными.
На данный момент поддерживается только `cidrs`.

### api.log(msg)

Записывает сообщение в лог приложения.

## Бинарный формат SRS

Формат sing-box SRS хранит скомпилированные IP CIDR-диапазоны в zlib-сжатом
бинарном файле. Поддерживаются версии с 1 по 5. Адаптер извлекает
`ip_cidr`-записи для IPv4 и IPv6 префиксов.

## Ограничения и безопасность

Ограничиваются разрешённые хосты, количество запросов, размеры ответов, общий
объём загрузки и время выполнения. Хост URL фида разрешён автоматически;
дополнительные хосты указываются у адаптера в админке.

Go-приложение проверяет и нормализует каждый CIDR, после чего атомарно
заменяет предыдущий снимок. Ошибка скрипта или синхронизации не удаляет
последний успешный снимок.

## Управление адаптерами

### Редактор

У каждого адаптера есть отдельная страница редактора. Ошибки синтаксиса и
выполнения показываются на ней с позициями в JavaScript и stack trace, а
отправленный текст сохраняется в форме. Встроенные адаптеры можно сбросить к
версии из дистрибутива: восстанавливаются исходные имя, текст и разрешённые
хосты, после чего ревизия увеличивается.

### Тестирование

Существующий адаптер можно протестировать на одном из назначенных ему фидов из
админки. Для теста используется текст, находящийся в редакторе, включая
несохранённые изменения. Показываются первые 100 нормализованных CIDR, при этом
каталог, статус фида, ревизия адаптера и состояние BGP не изменяются.

### Резервные копии

При редактировании или удалении адаптера его предыдущий исходный код
сохраняется в `WDBGP_ADAPTER_BACKUP_DIR` (по умолчанию
`<db_dir>/backup/adapters`). Директория создаётся автоматически. Задайте
пустую строку в `WDBGP_ADAPTER_BACKUP_DIR`, чтобы отключить бэкапы.
`WDBGP_ADAPTER_BACKUP_MAX` (по умолчанию 10) задаёт максимальное количество
хранимых копий на адаптер; старые файлы удаляются первыми. 0 — без ограничений.
